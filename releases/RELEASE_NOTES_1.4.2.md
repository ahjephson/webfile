# WebFile 1.4.2

WebFile 1.4.2 fixes uploads left pending after request failures and hardens task status and error reporting.

## Changes

- Mark upload tasks as failed when a request fails, including HTTP errors generated by nginx or another reverse proxy. If the failure report cannot reach WebFile, the browser retains it across page reloads and retries when connectivity returns.
- Preserve partial upload data for resumable retries. Delayed failure reports and progress updates cannot overwrite a newer upload attempt or an already completed upload.
- Refresh task status after upload errors and periodically reconcile active tasks, so missed WebSocket updates do not leave uploads, copies, moves, deletes or archive tasks visibly pending.
- Finalize upload cancellation and unexpected task or cleanup failures through the task lifecycle, retaining failure history and releasing background worker slots.
- Show clear public error messages instead of raw filesystem, archive-tool or worker diagnostics. Internal server paths remain in server logs, and previously saved task errors are sanitized before display.

## Validation and deployment

- Release validation covers backend tests and vet, production/PAM coverage, frontend build and dependency audit, source and binary vulnerability scans, script tests, complete Chromium and WebKit suites, mounted-path checks, and package checksum and metadata checks. Publication reuses the package validated by CI for the exact main commit.
- No configuration migration is required from 1.4.1. Refresh open browser tabs after upgrading to load the updated upload client. The package targets Linux AMD64 with systemd on Debian or Ubuntu. Clean-host installation/upgrade and physical-tablet checks remain manual validation tasks.
